# 事实链条（Fact Chain）注入使用说明

## 功能概述

事实链条注入是一种故障注入规则，用于测试 Agent 系统在超长上下文中的信息提取和连接能力。该规则将原始消息中的有用信息拆解为多个逻辑不连续的片段，并将这些片段穿插到长文本（PG-19 书籍文本）的不同位置，模拟上下文过长导致的信息分散场景。

## 实现原理

### BABILong 模式

参考 BABILong 基准测试的模式：
- **事实 1**（位置 10% 处）：插入第一个事实片段
- **事实 2**（位置 50% 处）：插入第二个事实片段
- **事实 3**（位置 90% 处）：插入第三个事实片段
- 如果有更多片段，会在 30%、70% 等位置插入

### 关键特性

1. **无需 LLM 生成**：使用随机插入和简单文本操作，不需要调用大模型
2. **自然插入**：事实片段会插入到文本的句子或段落边界，保持文本的自然流畅
3. **信息完整性**：所有原始消息中的关键信息都会被保留，只是分散在不同位置

## 配置方法

### 1. 在 `injector_config.yaml` 中启用

```yaml
llm_injection:
  enabled: true
  rule_id: fact_chain_injection
  # 其他配置项...
```

### 2. 规则已在 `rules.yaml` 中定义

规则 ID: `fact_chain_injection`

## 使用示例

### 测试消息示例

```
老王今天穿了一件红色的衬衫。
老王在公园丢了一张蓝色的卡片。
捡到蓝色卡片的人会得到一件和失主衬衫颜色一样的礼物。
```

### 注入过程

1. **拆解消息**：将消息按句子拆分为多个事实片段
2. **加载 PG-19 文本**：从 `/Users/ximenajia/CODE/Tester/pg19/downloaded_data/10146.txt` 加载长文本
3. **插入片段**：在文本的 10%、50%、90% 等位置插入事实片段
4. **返回结果**：返回包含插入片段的超长文本

### 结果示例

原始消息（118 字符）会被注入到 PG-19 文本（249,431 字符）中，结果文本长度约为 249,535 字符。

关键事实（如"红色"、"蓝色"、"卡片"、"礼物"、"衬衫"、"老王"）会分散在文本的不同位置，需要 Agent 在整个上下文中提取和连接这些信息。

## 注意事项

1. **PG-19 文本文件路径**：默认使用 `/Users/ximenajia/CODE/Tester/pg19/downloaded_data/10146.txt`
2. **片段数量**：至少需要 3 个事实片段，最多支持 5 个
3. **插入位置**：片段会插入到文本的句子或段落边界，保持自然流畅
4. **性能**：由于不需要 LLM 调用，注入速度很快
